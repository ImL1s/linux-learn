# 管道通訊 (Pipe)

## 📖 概念介紹

**管道 (Pipe)** 是 Linux 中最基本的進程間通訊 (IPC) 機制之一。它提供了一種讓兩個進程進行單向數據傳輸的方式。

### 管道的特性

- **半雙工通訊**: 數據只能單向流動
- **親緣關係**: 只能在有親緣關係的進程間使用（通常是父子進程）
- **FIFO**: 先進先出的數據流
- **字節流**: 傳輸的是無格式的字節流，沒有消息邊界
- **內核緩衝**: 數據存儲在內核的環形緩衝區中

## 🔧 系統調用

### pipe() 函數

```c
#include <unistd.h>
int pipe(int pipefd[2]);
```

- **參數**: `pipefd[2]` - 用於返回兩個文件描述符的數組
  - `pipefd[0]`: 讀端
  - `pipefd[1]`: 寫端
- **返回值**: 成功返回 0，失敗返回 -1

### 相關操作

- `read(pipefd[0], buf, count)` - 從管道讀取數據
- `write(pipefd[1], buf, count)` - 向管道寫入數據
- `close(pipefd[0])` 或 `close(pipefd[1])` - 關閉管道端

## 📊 執行流程圖

```
父進程創建管道
    |
    ├─> pipefd[0] (讀端)
    └─> pipefd[1] (寫端)
    |
fork() 創建子進程
    |
    ├─> 父進程                  ├─> 子進程
    |   - 關閉 pipefd[0]        |   - 關閉 pipefd[1]
    |   - 向 pipefd[1] 寫入     |   - 從 pipefd[0] 讀取
    |   - 關閉 pipefd[1]        |   - 關閉 pipefd[0]
    |   - wait() 等待子進程     |   - exit() 退出
    └─> 退出                    └─> 退出
```

## 💡 重要概念

### 1. 為什麼要關閉不使用的端？

```c
// 子進程只讀取
close(pipefd[1]);  // 關閉寫端

// 父進程只寫入
close(pipefd[0]);  // 關閉讀端
```

**原因**:
- 避免文件描述符資源浪費
- 確保 EOF 能被正確檢測到
- 防止潛在的死鎖

### 2. 管道的阻塞特性

- **讀端**: 當管道為空時，`read()` 會阻塞
- **寫端**: 當管道滿時，`write()` 會阻塞
- **EOF 檢測**: 所有寫端關閉後，`read()` 返回 0
- **SIGPIPE**: 所有讀端關閉後，`write()` 會收到 SIGPIPE 信號

### 3. 管道容量

- Linux 管道緩衝區大小通常為 **64KB**
- 可通過 `/proc/sys/fs/pipe-max-size` 查看最大值
- 使用 `fcntl(F_SETPIPE_SZ)` 可調整大小

## ❓ 常見問題

**Q1: 管道和文件有什麼區別？**
- 管道是內存中的緩衝區，沒有對應的磁盤文件
- 管道數據讀取後就消失，文件可以反復讀取
- 管道有容量限制

**Q2: 什麼時候使用管道？**
- 父子進程間簡單的單向通訊
- 不需要持久化的臨時數據傳輸
- Shell 中的管道操作符 `|` 就是基於此實現

**Q3: 管道的限制是什麼？**
- 只能單向通訊
- 只能用於有親緣關係的進程
- 無法廣播給多個讀者

## 📚 延伸學習

- **命名管道 (FIFO)**: 用於無親緣關係的進程通訊 → 參見 `03-fifo/`
- **popen/pclose**: 高級管道接口，結合了 fork、exec 和 pipe
- **socketpair**: 創建雙向管道

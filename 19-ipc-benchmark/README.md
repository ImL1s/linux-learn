# IPC 性能對比工具

## 📖 簡介

IPC Benchmark 是一個性能測試工具，用於對比不同 IPC（進程間通訊）機制的性能表現，幫助開發者選擇最適合的 IPC 方案。

## 📁 範例文件

- `ipc_benchmark.c` - IPC 性能對比工具（900+ 行）

## 🎯 測試的 IPC 機制

### 1. 匿名管道 (Anonymous Pipe)

**特點**:
- 最簡單的 IPC 機制
- 只能用於父子進程
- 單向通信（需要兩個管道實現雙向）
- 數據流式傳輸

**適用場景**:
- 父子進程通信
- 命令管道（如 `ls | grep`）

### 2. FIFO (命名管道)

**特點**:
- 基於文件系統的管道
- 可用於無關進程
- 單向通信
- 持久化（進程退出後仍存在）

**適用場景**:
- 無關進程通信
- 日誌收集
- 簡單的客戶端-服務器模型

### 3. System V 共享內存

**特點**:
- 最快的 IPC 機制
- 直接內存訪問，無需數據複製
- 需要額外的同步機制（信號量）
- 進程退出後需要手動清理

**適用場景**:
- 大量數據傳輸
- 高性能要求
- 實時系統

### 4. System V 消息隊列

**特點**:
- 結構化消息傳遞
- 支持消息優先級
- 內核緩衝
- 相對較慢（需要數據複製）

**適用場景**:
- 結構化消息
- 需要優先級
- 異步通信

### 5. Unix Domain Socket

**特點**:
- 網絡風格的 API
- 雙向通信
- 支持 SOCK_STREAM 和 SOCK_DGRAM
- 比 TCP Socket 快（無需網絡協議棧）

**適用場景**:
- 需要雙向通信
- 客戶端-服務器架構
- 需要連接管理

## 🔨 編譯與運行

### 編譯

```bash
gcc -o ipc_benchmark ipc_benchmark.c -lrt

# 或使用 Makefile
make ipc-benchmark
```

### 基本使用

```bash
# 運行所有測試（默認 1MB 數據）
./ipc_benchmark

# 輸出示例：
# ========================================
#        IPC 性能對比測試
# ========================================
# 測試數據大小: 1.00 MB
# 塊大小: 4.00 KB
# ========================================
#
# IPC 機制             | 吞吐量        | 延遲       | 總時間
# ---------------------|---------------|------------|------------
# Anonymous Pipe       |   450.23 MB/s |    8.88 us |  0.002 s
# FIFO (Named Pipe)    |   420.15 MB/s |    9.52 us |  0.002 s
# Shared Memory        |  2500.67 MB/s |    1.60 us |  0.000 s
# Message Queue        |    85.34 MB/s |   46.87 us |  0.012 s
# Unix Domain Socket   |   680.45 MB/s |    5.88 us |  0.001 s
```

### 自定義測試

```bash
# 測試 10MB 數據
./ipc_benchmark --size 10M

# 自定義塊大小
./ipc_benchmark --size 1M --block 8K

# 只測試特定機制
./ipc_benchmark pipe shm          # 只測試管道和共享內存
./ipc_benchmark socket             # 只測試 Unix Socket
```

### 完整參數

```bash
./ipc_benchmark [選項] [機制...]

選項:
  --size SIZE     測試數據大小（默認: 1MB）
                  支持: 1K, 1M, 10M 等
  --block SIZE    塊大小（默認: 4KB）
  --help          顯示幫助

機制:
  pipe            匿名管道
  fifo            FIFO（命名管道）
  shm             共享內存
  msgq            消息隊列
  socket          Unix Domain Socket
```

## 📊 性能對比分析

### 典型性能數據（1MB 數據傳輸）

| IPC 機制 | 吞吐量 | 延遲 | 特點 |
|---------|--------|------|------|
| **共享內存** | ⭐⭐⭐⭐⭐ (最快) | ⭐⭐⭐⭐⭐ (最低) | 直接內存訪問 |
| **Unix Socket** | ⭐⭐⭐⭐☆ | ⭐⭐⭐⭐☆ | 靈活，雙向 |
| **管道** | ⭐⭐⭐☆☆ | ⭐⭐⭐☆☆ | 簡單，單向 |
| **FIFO** | ⭐⭐⭐☆☆ | ⭐⭐⭐☆☆ | 類似管道 |
| **消息隊列** | ⭐⭐☆☆☆ (最慢) | ⭐⭐☆☆☆ (最高) | 結構化消息 |

### 性能排名（快到慢）

1. **共享內存** - 2000-3000 MB/s
   - 直接內存訪問，無數據複製
   - 需要額外同步機制

2. **Unix Domain Socket** - 600-800 MB/s
   - 內核優化，無網絡協議棧
   - 支持雙向通信

3. **匿名管道** - 400-500 MB/s
   - 內核緩衝
   - 簡單高效

4. **FIFO** - 400-500 MB/s
   - 性能與管道相近
   - 基於文件系統

5. **消息隊列** - 80-100 MB/s
   - 數據複製開銷大
   - 支持結構化消息

## 🎯 選擇建議

### 根據場景選擇

**高性能數據傳輸** → **共享內存**
```
場景: 視頻處理、大數據分析
優點: 最快，零複製
缺點: 需要手動同步
```

**靈活的客戶端-服務器** → **Unix Socket**
```
場景: Web 服務器、數據庫連接
優點: 雙向，連接管理
缺點: 有一定開銷
```

**簡單的父子進程** → **匿名管道**
```
場景: 命令管道、簡單通信
優點: 最簡單
缺點: 只能父子進程
```

**無關進程通信** → **FIFO**
```
場景: 日誌收集、進程協作
優點: 基於文件系統
缺點: 單向通信
```

**結構化消息** → **消息隊列**
```
場景: 任務隊列、消息中間件
優點: 支持優先級
缺點: 性能較低
```

### 根據需求選擇

| 需求 | 推薦方案 | 備選方案 |
|------|---------|---------|
| **最高性能** | 共享內存 | Unix Socket |
| **雙向通信** | Unix Socket | 兩個管道 |
| **簡單實現** | 匿名管道 | FIFO |
| **結構化數據** | 消息隊列 | Unix Socket |
| **大量數據** | 共享內存 | - |
| **跨網絡** | TCP Socket | - |

## 💡 使用技巧

### 1. 多次測試取平均

```bash
# 運行 5 次取平均值
for i in {1..5}; do
    ./ipc_benchmark --size 10M
done
```

### 2. 測試不同數據大小

```bash
# 測試小數據（1KB）
./ipc_benchmark --size 1K

# 測試中等數據（1MB）
./ipc_benchmark --size 1M

# 測試大數據（100MB）
./ipc_benchmark --size 100M
```

### 3. 對比塊大小影響

```bash
# 小塊（1KB）
./ipc_benchmark --size 1M --block 1K

# 中塊（4KB，默認）
./ipc_benchmark --size 1M --block 4K

# 大塊（64KB）
./ipc_benchmark --size 1M --block 64K
```

## 🔍 實驗結果分析

### 觀察 1: 共享內存最快

**原因**: 直接內存訪問，無需數據複製

```
傳統 IPC: 用戶空間 → 內核 → 用戶空間（兩次複製）
共享內存: 用戶空間直接訪問（零複製）
```

### 觀察 2: 消息隊列最慢

**原因**:
- 數據需要複製到內核緩衝區
- 消息結構處理開銷
- 系統調用開銷

### 觀察 3: 塊大小影響性能

**小塊** (1KB):
- 系統調用次數多
- 上下文切換開銷大
- 適合低延遲場景

**大塊** (64KB):
- 系統調用次數少
- 高吞吐量
- 適合批量傳輸

## 📚 學習要點

### 核心概念

1. **吞吐量 vs 延遲**
   - 吞吐量: 單位時間傳輸數據量（MB/s）
   - 延遲: 單次操作的時間（微秒）

2. **零複製技術**
   - 共享內存實現零複製
   - 減少 CPU 和內存開銷

3. **系統調用開銷**
   - 每次 IPC 操作都需要系統調用
   - 批量操作可減少開銷

### 實踐經驗

1. **性能不是唯一標準**
   - 考慮實現複雜度
   - 考慮可維護性
   - 考慮跨平台性

2. **根據實際需求選擇**
   - 不要過度優化
   - 先測試再決定

3. **組合使用**
   - 共享內存 + 信號量（數據 + 同步）
   - Unix Socket + 共享內存（控制 + 數據）
